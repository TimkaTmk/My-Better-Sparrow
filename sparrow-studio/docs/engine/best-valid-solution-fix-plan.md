# План исправления `Best valid solution`

## Цель

Для больших раскроев не отклонять допустимые раскладки из-за медленного квадратичного поиска минимального зазора; при этом не выдавать непроверенный или геометрически некорректный результат за проверенный. Показывать пользователю причину, если очередной кандидат не проходит проверку.

## Шаги

- [x] Проследить путь `candidate` от Rust/WASM через worker и независимую проверку до кнопки `Best valid solution`.
- [x] Заменить вложенное сравнение сегментов на точный поиск минимума через BVH/AABB-деревья; убрать лимит, который превращал превышение бюджета в `failed`.
- [x] Не повторять проверку самопересечений исходного контура для каждой жёстко преобразованной копии; добавить путь валидации уже нормализованного документа для solver worker.
- [x] Записывать длительность проверки в диагностическую историю.
- [x] Показывать текущую причину отклонения кандидата во время поиска и очищать её после успешной проверки.
- [x] Обновить этот план и аналитический отчёт по итогам изменений.

## Критерии готовности

- Проверка зазора остаётся точной: быстрый поиск не пропускает пару сегментов, которая может дать меньший зазор.
- Корректная геометрия с отверстиями и ненулевым зазором может стать `Best valid solution` без искусственного отказа из-за счётчика 50 млн пар.
- Если точная проверка действительно находит нарушение, кандидат остаётся только в `Live search`, а сообщение об отказе видно до остановки запуска.
- Непроверенный или ошибочный кандидат никогда не считается `passed`.

## Статус

Кодовые изменения и production-сборка готовы. Уже открытый старый запуск не подхватит обновлённые worker-файлы; для применения нужно открыть обновлённую сборку и заново запустить раскрой. Точное подтверждение скорости требует повторного запуска исходного проекта примерно со 100 деталями.
